جدول بندانگشتی در این اندازه **قابل خواندن نیست**؛ چند تلاش با بزرگ‌نمایی ۳× و ۴×،
خاکستری و کنتراست بالا هم ارقام را برنگرداند (خروجی چیزی شبیه `۳۵۵0 … ۱۳۵9` بود، نه قیمت).
هیچ موتور OCR از این ارتفاع ۱۵۰ پیکسلی شش ستون عدد درنمی‌آورد؛ اپ در این حالت عدد
نمی‌سازد و همان را می‌گوید.

## نتیجهٔ خط لوله (همان کدِ داخل اپ)

```
$ dart run tool/photo_pipeline.dart /tmp/ocr_full.txt

== stored rows: 0 (noise 1, outOfWindow 0, duplicates 0) ==
== what the picture held ==
  خانواده محصول: میلگرد
  شهر از تلفن: تهران (پیش‌شماره 021)
  نقشه: لینک کوتاه؛ بازکردن لازم دارد
  مبلغ‌های خوانده‌شده: هیچ مبلغی خوانا نبود
```

یعنی سه اشکالی که گزارش کردید:

| اشکال گزارش‌شده | وضعیت با این عکس |
| --- | --- |
| 「از شماره تلفن شهر را تشخیص نداد」 | **رفع شد** — `02191323000` ← پیش‌شمارهٔ ۰۲۱ ← **تهران**. شمارهٔ همراه هم دیگر شهر نمی‌سازد. |
| 「آدرس گوگل مپ بود ولی مکان شناسایی نشد» | **رفع شد (با اینترنت)** — لینک کوتاه حالا باز می‌شود؛ برای همین لینک خود گوگل پاسخ `Dynamic Link Not Found` داد (یا OCR یک کاراکتر کد را اشتباه خوانده یا لینک منقضی است). اپ همین را ثبت می‌کند: «لینک کوتاه باز نشد؛ مکان از آن استنتاج نشد» و هیچ مختصاتی نمی‌سازد. با لینک سالم، شهر/مختصات از خود آدرس خوانده می‌شود (آزمون `test/maps_resolver_test.dart`). |
| 「در نتیجه قیمت را هم تشخیص نداد» | **محدودیت عکس، نه کد** — جدول در این اسکرین‌شات خوانا نیست. با همان پست به‌صورت متن یا با عکس اصلی جدول، ردیف‌ها استخراج می‌شوند (آزمون «پستی با همین شکل ولی قیمت خوانا» در `test/searcher_test.dart`). |

## چه چیزی از این عکس بهتر شد

- `Searcher.cleanOcrText`: حذف کاراکترهای جهت‌دهی (`U+200E/200F/202A…`) که ایتا و OCR
  دور هر خط فارسی می‌گذارند، و **چسباندن لینکی که حباب چت دو خط کرده**
  (`https://maps.app.goo.gl` + `/KyKq5e2b7vrHCjxb9`).
- `MapsResolver`: بازکردن لینک کوتاه روی همان اتصال اپ (HEAD، بعد GET)، خواندن
  `Location` یا نشانی داخل صفحه (`rel=canonical`/`og:url`)، حداکثر ۳ پرش و ۷ ثانیه،
  و ثبت صریح شکست.
- `Searcher.imageEvidence`: وقتی عکس ردیف قابل‌ثبتی ندارد، اپ می‌گوید **چه دید**
  (خانواده، شهر از تلفن، وضعیت نقشه، تعداد مبلغ خوانا) به‌جای پیام مبهم.
- `OcrChannel.kt`: دو پاس OCR (تصویر اصلی + نسخهٔ خاکستری/کنتراست‌بالا و بزرگ‌تر) و
  انتخاب پاس بهتر بر اساس تعداد حروف فارسی و رقم — برای عکس‌های کم‌نور و کوچک.

## اکنون خودکار است

این تحلیل با فراخوانی دستی انجام شد؛ از نسخهٔ بعد همین مسیر خودکار است: اسکن، عکس پست را
خودش برمی‌دارد، دانلود می‌کند و می‌خواند (بدون انتخاب فایل). برای اینکه قیمت‌های همین پست
هم دربیایند، عکس اصلی جدول باید در دسترس باشد (نه بندانگشتی چت)؛ آن‌وقت همان مسیر
`PhotoScanner → TextPriceEngine → Searcher` ردیف‌ها را در تب قیمت‌ها ثبت می‌کند.
